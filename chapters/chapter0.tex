\section{大学阶段的基本认识}
自己对大学班主任角色的定位，就两点：
\begin{itemize}
\item 站在学生的角度上，和班上学生一条阵线；
\begin{itemize}
\item 不整虚的，讲实在话；
\item ... ...
\end{itemize}
\item 辅助班上学生顺利毕业
\begin{itemize}
\item 辅助走得高的，走的更高远；辅助走得慢的，跟上；
\item 帮助引进提升的机会，如比赛和科研；
\item ... ...
\end{itemize}
\end{itemize}
教课和班主任基本是用爱发电，珍惜关心你们的老师。


{\bf 作为大学生的基本认识：}
\begin{itemize}
\item 已是成年人，要对自己的前途命运负责。（没人像高中那样天天督促你，一个学期就偶尔几次）

\item 自觉、自律保毕业。【Level 1】

\item 主动让自己走的更高远。【Level 2】

\item 打开格局。【Level 3】

\item 思考：自己在Level 几？

\item 尽早形成自己的毕业愿景。大学的学习要围绕自己的毕业愿景展开，并为之努力、行动，毕业愿景不要求固定不变，可以变化，核心在于为之努力。一开始就要有大方向，不清晰没关系，及时明确。
\end{itemize}

外部环境发生变化：父母不在身边、老师不再贴身督促，更需要自觉、自律。
主动，是让自己忙碌起来，时间用在刀刃上、主动抓住机会。

做人做事的态度（很多时候机会只有一次）：
\begin{itemize}
\item 思考未来，思考自己的位置；
\item 第一印象很关键；
\item 守时是基本。
\end{itemize}




{\bf 专业课学习：}
\begin{itemize}
\item 基本认识：
\begin{enumerate}
\item 宁大课程都不难，英语四六也不难，觉得难的话，很可能是方法不对。

\item {\bf 记笔记很关键：}知识储备很重要，但是要记笔记，沉淀下来成为自己东西。专业课，学了又忘了，不记笔记肯定会忘记的。辛辛苦苦学习，丢掉很可惜，记笔记很关键，只有记下笔记才是你的，书本上的永远是别人的。而且笔记最好电子化，推荐\LaTeX 。

\item {\bf 最重要的是：}自己的知识的掌握与沉淀需要反复的打磨过程，丰富它，调整它，使得符合自己的思维逻辑。这就需要电子版的笔记，可以理解为一个可以不断升级的笔记，不断成长的笔记。笔记的成长，也就是自己对知识掌握的成长。

\item {\bf 详略得当，核心是学习能力}，随时丢，随时捡。\footnote{这是最适合当前环境背景的策略。前面说了外国情况，但不能照搬照抄，要符合我们当前情形，不要求专业课学习多好，或多喜欢，你要保证合格最终拿到学位证就行。一旦毕业，拿到学位证，除了争保研名额，专业课分数60和100可以说没区别，因为用人单位不关心分数，而是学位证和额外的能力，招研究生也是一样。}
\end{enumerate}

\item 基本方法：
\begin{enumerate}
\item  每门专业手头常备3本或以上参考书。因为，每本书都有自己的特点，每个人在不同的特点上理解是有容易或难度的，需要我门找到容易的理解点。

\item 抓住基本概念，基本推导，要自己推，记笔记很关键。

\item 重点关注平时作业和最后几节课；平时分要拿齐；考试卷面一定要多写。

\item 发达国家名校的课程学习一般课上松、考试难。除申请国外研究生需要刷分数绩点外，毕业就业和考研一般只认学位，几乎没有人关心本科课程分数。精力有限，以自己未来发展方向为中心，水课划水，核心课认真学。全面扎实的基本概念最重要，并不需要特别深入；入职或升学后自然会要求深入。

\item 英语要过六级，并兼顾学习、生活英语。作为物理专业，要会一门编程语言，推荐 Python。
\end{enumerate}

\end{itemize}

\paragraph{素描学习法}
这种方法是从网络视频「普通物理——台湾交通大学李威仪」学来的。认识事物是不断反复的过程：先画轮廓，再不断丰富细节。

\paragraph{正确做题}
做题是很重要的。自然界是没有答案给你的。平时做一道题无疑是一次小小的探索。把自己有的想法完全写出来，这就是思维的过程。平时做题就是解决问题，可以动用身边的一切资源，大胆查找资料（不是找直接的答案）。平时做题是知识的运用和方法的训练，考试做题是检测，本质不一样。


{\bf 课程外的加分项：}
\begin{itemize}
\item 基本认识：
\begin{enumerate}
\item 摒弃高中意识，大学注重课外能力，大学强调的是学习能力。（这里的“大学”仅适用宁大，其他学校不评论，不一定适用）

\item 学位证只能让你站在起跑线上，除了第一、第二名有保研优势外，只要拿到学位证第三名和最后一名没有区别！\footnote{我不确定我们有多少保研名额，这里只是举例} 一旦拿到学位证，表明大家都到起跑线了。但是课程外的加分项可以让你先跑了好几圈，再开始和别人比赛，到时别人再怎么加速跑也是追不上你的。

\item 现在就是尝试的时候，不要怕失败。年轻时的失败是本钱！
\end{enumerate}

\item 具体建议：
\begin{enumerate}
\item 找点加分事情做：1、减轻毕业时的压力；2、提高毕业时的竞争力；3、分散将来的能力需求。
不需要特别长的时间，但是要\underline{有规划的投入并取得收获}（六级等考证、比赛等）

\item 思考一个问题：设想一下，现在就毕业了，要找工作或研究生面试，要写简历。你的简历上怎么写自己呢？
\end{enumerate}
\end{itemize}


{\bf 参加比赛的意义：}

\begin{enumerate}
\item 比赛可以强化基本技能，这些技能往往是实用技能，很重要，但并不是最重要的！

\item 比赛是一个project，完成一个project，或者说\underline{完成一个project的流程才是最重要的！}
因为无论进入公司还是科研团队都是做project，而做project基本流程或框架都是相同的，只是内容和程度不同。所以强调完成一个project的经历！

\item 一个project并不仅仅是做技术，还有组织、管理，还有战略、策略。这几个方面，相互渗透，但是每个人擅长的点是不同的。通过做project，发现自己的不足，强化自己的优势。

\item 一个project分成四方面：
\begin{itemize}
\item 是技能强化或着是学习能力；

\item 团队内部的协调能力（与人打交道的能力）；

\item 寻求外部支持的能力（向高级别获得帮助的能力）；

\item 答辩、讲故事的能力。
\end{itemize}

\end{enumerate}

\subsection{文献管理的基本思想}
\begin{itemize}
\item 平等的看待每一篇文献。不需要专门的、特别的去存储某些文献。文献的时效性太短了，发现多年前的Nature、Science 正刊等对现在没有任何参考意义。

\item 文献多元分类。每篇文献有不同的标签。

\item 文献不同平台、设备的同步。常见的应用场景是，工作电脑下载了文献，然后用带手写笔的设备去细看、标记。
\end{itemize}
仅仅靠本地创建文件夹的方式去管理，是非常不方便的。需要采用专业的文献管理软件，\sout{非常推荐Zotero}（太臃肿了，正在自己开发文献管理工具）。

\section{自然科学论文写作}
\subsection{心得体会}
写论文，总觉得很难下笔，写起来总是很痛苦困难。为什么？
因为写出来与发表的文章相差太远了。我想说的{\textbf 第一点}是：心态摆正。做一件事情不要抱着一遍就做好的心态，往往要反复多次，打磨N遍。{\textbf 第二点}是：先意思后句法。先把大脑中的意思写出来，再来雕琢语句。先把大脑中的想法写清楚，怎么好写怎么来，甚至中英文混搭。


\subsection{摘要（Abstract）}
摘要一般5到6句话。
\begin{itemize}
\item 第一句：大背景；
\item 第二句：领域中有什么问题、我想做什么、有什么是未知的、有什么需要做的；
\item 有些文章不写第一句、第二句
\item 第三句：我用什么方法研究了什么东西；
\item 第四、五句：有什么结果。或加一句分析一下；
\item 最后一句：意义（重要性）。
\end{itemize}


\subsection{引言（Introduction）}
引言的写作直接影响到读者对文章进一步了解的兴趣， 建议包括以下内容\footnote{参考自物理学报的投稿模板}：
\begin{enumerate}
\item 本研究领域背景的综述；
\item 其他学者已有研究成果的详细描述；
\item 陈述为什么需要进行更多的或进一步的研究；
\item 阐述作者本项研究的目的和创新性；
\item 简述本文开展的研究工作；
\item 本项研究结果的意义(可选项)。
\item 特别指出的是, 希望在引言部分介绍和引用国内外期刊中本研究领域的最新研究成果, 以帮助读者清楚了解该领域的最新进展及本文的创新点。
\end{enumerate}





\section{国家自然科学基金申请书的写作}
参考资料：一些讲座、同事老师经验和自己的体会。【不注明出处】
\subsection{思想层面}
\subsubsection{基本认识——“向国家要钱”}
\begin{itemize}
\item 基础科研可以说是没有直接经济产出的。未来也是可能有也可能没有，而且时间也是长短不一，一般很长。所以基础科研不挣钱的。
\item 但是科研又是需要钱的。所以需要去“要”钱。向“谁”要？
\item 向“别人”要钱，所以要按人家要求来，要说服“别人”。
%很难自己对什么感兴趣，就研究什么。
\end{itemize}


\subsubsection{国家和自己的定位}
\paragraph{国家基金的定位}
\begin{itemize}
\item 基础研究（不是工程问题）。
\item 基金不是产品开发，基金是解决局部问题，局部的基础科学问题研究。
\end{itemize}

\paragraph{自己的定位}
\begin{itemize}
\item 国家需求的一小点
\item 交叉学部（注意交叉融合）
\end{itemize}


\subsubsection{指导思想}
\begin{itemize}
\item 如何写好一个本子？解决一个问题，讲好一个故事。

\item 基金如战事，“谋”则胜：认真谋划，积极请教，提前布局，方得始终。

\item 不可打酱油心态，要不断打磨本子。

\item 广结善缘：评阅人先看论文，再看人。文章->团队出身->内容。注意选口。
\end{itemize}


\subsubsection{基本认识}
\begin{itemize}
\item 千万不要有标点符号等错误。
\item 专家在挑刺，10分钟看本本。
\item 让大同行看懂，让小同行似懂非懂。
\item 系统送审，大同行评审（小学校、年青老师）。
\item 关键词要选好，评阅人通过关键词分配。
\end{itemize}


\subsubsection{整体思路}
\begin{itemize}
\item 立项依据非常重要
\item 借文献说出不足之处
\item 千万不要太细
\item 可行性分析起打补丁的作用
\item 修补性创新（改进型）
\item 研究基础与工作条件（注意合作单位；人不够，合作很关键；个人基础薄弱，团队很重要。）
\item 图文并茂，图就在图注中解释，不用在正文中解释
\item 小四号，1.5倍行距，楷体
\item 不是重点的不要浪费太多字，精炼
\item 前后呼应注重内在逻辑
\end{itemize}


\paragraph{三要素}
\begin{enumerate}
\item 研究对象
\begin{itemize}
\item 研究主体是什么？
\item 应用的领域是否重要？
\item 存在的问题是否为痛点问题？
\end{itemize}

\item 需要解决的问题

\item 解决问题的方法：科学方法
\end{enumerate}


\paragraph{说清楚三个问题}
\begin{enumerate}
\item 项目研究的内容值得做；
\item 项目研究的内容能够做好； 
\item 项目研究的内容我能做的更好。
\end{enumerate}

选题极为关键，申请书撰写规范极为重要，创新性和科学性决定成败。

\subsection{具体写作层面}
\subsubsection{选题}
\begin{itemize}
\item 选题应以问题为导向，不要以方法为导向。拿着所谓的“新方法”去找应用场景，由于对研究主体说不清道不明，往往被从根上被判为是“伪命题”。

\item 科学问题不要包罗万象，解决系统的所有问题。要“小题深做”，往下挖掘，不是面面俱到。

\item 尚未解决或新生的科学问题（聚焦到一个点或两个点，注意交叉创新）

\item 挑选有“吸引眼球”的应用领域非常重要。
	\begin{itemize}
	\item 同样的科学问题可以应用到不同领域
	\item 应用领域要拔高
	\end{itemize}
\item 方法源于问题。
\end{itemize}



\subsubsection{标题}
\begin{itemize}
\item {\color{red} 从题目中要能看出本本的轮廓。}

\item 理清楚了基金的三个基本要素，取名字时要集中体现三个基本要素。要求：名字中要明确研究对象、明确要解决的问题、明确采用的方法（或者突出特殊条件），比如：基于XX方法的XX对象XXX问题研究；或者：某种特点条件下某研究对象的什么问题研究。

\item 忌讳名字大而空，忌讳：某某关键技术的研究、某某重大技术的研究、某某系统的研究等；基金是基础研究，不是技术研究，也不是应用研究，名字中尽量不要突出技术或应用。

\item 好标题：具体、新意、务实

\item 研究对象是个名词，对象要具体。面上、青年研究某个关键问题。

\item 题目由：对象、问题、方法构成，惟一可缺的是方法。
\end{itemize}




\subsubsection{摘要}
\begin{itemize}
\item {\color{red}从摘要能看出申请书的骨骼构架，它包含：背景及问题、目标、内容、意义。}
\item 摘要要吸引人，眼前一亮，新的东西
\end{itemize}

写一个精炼的摘要，做到多一字则多，少一字则没表达清楚。要求：
\begin{itemize}
\item 第一句话：研究对象的背景及存在的问题；（领域背景问题）
\item 第二句话：本项目拟采用什么方法解决哪些问题；（研究目标）
\item 第三句话：解决问题的具体内容；（研究内容）
\item 最后一句话：问题解决对所在领域的理论和现实意义。（研究意义）
\end{itemize}

摘要的书写规范概况起来：
\begin{itemize}
\item 本项目研究的东西在某个领域里至关重要，但是它存在某些问题需要解决。
\item 本项目拟采用某某方法来解决这个问题。
\item 具体的内容如下：
	\begin{itemize}
	\item[1)] 先做什么；
	\item[2)] 再做什么；
	\item[3)] 最后怎么样验证的，得到啥结论。
	\end{itemize}

\section{基本认识}
AI 助手（agent）不替代你想清楚问题，但能少写重复操作、少翻手册。写代码、改 \LaTeX、查报错、整理 git，都可以先问它。

当前常见的三类入口：
\begin{itemize}
\item 编辑器里：Cursor。对着打开的仓库边看边改。
\item 终端里：Claude Code、Codex CLI。在项目目录下任务，让它读文件、改文件、跑命令。
\item 聊天应用里：ChatGPT App（其中的 Codex）。先聊方案，再落到代码；也可以装桌面应用。
\end{itemize}
三者都要联网、要有各自账号。具体收费和地区可用性以官网为准，安装命令也会变，以官网为准。

\paragraph{怎么用}
用平常的话交代任务。任务对得上时，agent 会自己去读对应的 skill。要指定某一条时，直接点名，例如「用 brainstorming」，或「按 writing-plans 拆开」。

\paragraph{一般流程}
让它改一个项目时，默认按下面的顺序走。你点头，它才进入下一步。
\begin{enumerate}
\item \verb|brainstorming|：先问清楚要做什么，把设计分成几小段给你看。
\item \verb|using-git-worktrees|：设计通过后，另开一个工作区再改。
\item \verb|writing-plans|：把设计拆成可以逐条执行的小任务。
\item 按计划实现，两条路：
\begin{itemize}
\item \verb|subagent-driven-development|：一项一项做，做完一项查一项。
\item \verb|executing-plans|：按计划把任务做完，最后统一看一遍。
\end{itemize}
\item \verb|test-driven-development|：先写一个会失败的测试，再写刚好能通过的代码。
\item \verb|requesting-code-review|：对照计划看改动。有严重问题就停下来改。
\item \verb|finishing-a-development-branch|：验证通过后，再决定合并、提交 PR，或丢掉这次分支。
\end{enumerate}

\paragraph{其余 skills}
\begin{itemize}
\item \verb|systematic-debugging|：报错、测试失败或结果不对时用。先把原因找出来。
\item \verb|verification-before-completion|：它准备说「已经好了」时用。先跑验证，看过输出再下结论。
\item \verb|receiving-code-review|：收到评审意见时用。先核对意见是否成立，再改。
\item \verb|dispatching-parallel-agents|：有几件互不相干的事时用，分头同时做。
\item \verb|diagnosing-superpowers|：这次没有按上面的流程走时用。让它根据对话记录说明偏在哪里。
\item \verb|writing-skills|：要新写或修改一条 skill 时用。
\item \verb|using-superpowers|：一轮对话开始时用，先确定该读哪一条 skill。
\end{itemize}
名单会随仓库更新，以 \url{https://github.com/obra/superpowers} 的 README 为准。



\chapter{Git——程序和文档的版本管理}
\section{基本认识}
改程序、改论文、改笔记，文件名往往会变成「终稿」「终稿2」「真的终稿」。Git 把每一次有意义的修改记下来，需要时可以回到某一次，也可以把修改交给别人。它有图形界面，也有命令行。后文用命令行：步骤少，和 AI 助手对话时也可以直接把命令交给它。

Git 是 Linus Torvalds（林纳斯·托瓦兹）在 2005 年写的。他更早的作品是 Linux 内核。内核从 2002 年起用商业软件 BitKeeper 管理代码，对方当时给内核社区免费许可。2005 年，这份许可被收回。内核不能没有版本管理，Linus 决定自己写一套。这个名字是 Linus 的自嘲，不是一组英文单词的缩写。第一次提交的说明是：the information manager from hell。

2005 年 4 月 7 日的第一次提交，已经能用 Git 管理 Git 自己的代码。他后来回忆，写到这一步大约用了两周，具体天数自己也记不准。2005 年 7 月 27 日，他宣布把维护工作交给滨野纯（Junio C Hamano）。滨野纯一直维护到现在。

当时要替换的，是能撑住 Linux 内核这种规模的工具。\emph{Pro Git} 记下了他们给新系统定的目标：快，设计简单，支持大量并行分支，每台电脑都有完整历史，并且扛得住超大项目。对初学，先抓住三件事。

\begin{enumerate}
\item 每台电脑上都有完整历史。克隆下来的不只是最新的文件，而是全部提交。没有网络也可以提交。要和别人协作时，再把历史同步出去。GitHub、GitLab、Gitee（码云）是存放远程仓库的网站，它们不是 Git 本身。

\item 一次提交是当时整个项目的一份快照，用内容的哈希值命名。内容变了，哈希就变，历史就对不上，所以记录不容易被悄悄改掉。分支只是指向某一次提交的名字。新开一条分支，不必把文件再复制一份。

\item 修改先留在本地，确认之后才写入历史。同一份文件会经过三个地方：工作区是正在修改的目录；暂存区是这次准备提交的内容；本地库是已经写下的历史，放在项目里的 \verb|.git| 目录，不要删，也不要手改。远程仓库是本地库的另一份，用来和别人共享。
\end{enumerate}

\section{安装与使用}
\begin{xiaonao}[如何安装使用git]
你其实不用管，直接让你的AI助手帮你搞定。但是你需要简单了解git的基本用法和思想。
\end{xiaonao}

到官网下载安装：\url{https://git-scm.com/downloads}。

Debian / Ubuntu 也可以执行 \verb|sudo apt install git|。装好后运行 \verb|git --version|，能看到版本号即可。命令记不住就问 AI 助手。下面只留每天会碰到的几步。

\paragraph{签名}
每次提交都带名字和邮箱，一台电脑设一次：
\begin{lstlisting}[
  numbers=none,
  xleftmargin=2mm,
  framexleftmargin=2mm,
  columns=fullflexible,
  breaklines=true,
  upquote=true,
  basicstyle=\ttfamily\footnotesize,
  literate={"}{{\textquotedbl}}1
]
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
\end{lstlisting}
写提交说明时若要换编辑器，再执行 \verb|git config --global core.editor vim|。

\paragraph{提交}
在项目目录里：
\begin{enumerate}
\item \verb|git init| 建立本地库，目录里会出现 \verb|.git|。clone 下来的仓库不用再 init。
\item \verb|git status| 看哪些文件改过。
\item \verb|git add 文件| 放进暂存区。\verb|git restore --staged 文件| 从暂存区撤回，磁盘上的文件还在。
\item \verb|git rm --cached 文件| 是停止跟踪这个文件，文件本身不删。
\item \verb|git commit -m "说明"| 写入本地库。\verb|git commit -a -m "说明"| 把已经跟踪的文件的修改直接提交；新文件仍然要先 add。
\end{enumerate}

\paragraph{查看与回到旧版本}
\verb|git log| 看提交历史，\verb|git reflog| 连回退本身也记着。\verb|git diff| 比较工作区和暂存区；\verb|git diff 某次提交| 比较工作区和那一次快照。不写文件名就是整个项目。

\verb|git reset 某次提交| 回到那次提交，文件上还没提交的修改留着。加上 \verb|--hard| 会丢掉这些修改，执行前先看清 \verb|git status|。已经进过本地库的版本，可以用 \verb|git reflog| 再找回来。

\paragraph{分支}
\verb|git branch| 查看，\verb|git branch 名字| 新建，\verb|git checkout 名字| 切换。较新的写法是 \verb|git switch|。\verb|git branch -m 旧名 新名| 改名。

合并时先切到要接收改动的分支，再 \verb|git merge 另一分支|。若发生冲突，打开文件，删掉冲突标记，改到满意，然后 \verb|git add|，再 \verb|git commit|。这次提交不要在命令末尾再写文件名。

\subsection{第一次推送}
在网页上注册，新建一个空仓库。先不要勾选用 README 初始化，远程才是空的，本地可以直接推上去。

\begin{lstlisting}[
  numbers=none,
  xleftmargin=2mm,
  framexleftmargin=2mm,
  columns=fullflexible,
  breaklines=true,
  basicstyle=\ttfamily\footnotesize
]
git remote add origin 仓库地址
git push -u origin master
\end{lstlisting}
\verb|-u| 只需第一次。之后在这个分支上执行 \verb|git push| 即可。用 \verb|git remote -v| 核对地址。本书的例子用 \verb|master|。GitHub 新建仓库时常默认 \verb|main|，分支名要和网页上的一致。

网页上若已经有了初始提交，直接 push 会被拒绝。先执行下面这行，再 push。
\begin{lstlisting}[
  numbers=none,
  xleftmargin=2mm,
  framexleftmargin=2mm,
  columns=fullflexible,
  breaklines=true,
  basicstyle=\ttfamily\footnotesize
]
git pull --rebase origin master
\end{lstlisting}
两边各自已经有一段互不相关的历史时，才用下面这行。不要用 \verb|git push --force| 盖掉远程上已有的提交。
\begin{lstlisting}[
  numbers=none,
  xleftmargin=2mm,
  framexleftmargin=2mm,
  columns=fullflexible,
  breaklines=true,
  basicstyle=\ttfamily\footnotesize
]
git pull origin master --allow-unrelated-histories
\end{lstlisting}

\subsection{用 SSH 推送}
要用上一小节的 SSH 地址，先在本机生成密钥，把公钥交给网站。

\begin{lstlisting}[
  numbers=none,
  xleftmargin=2mm,
  framexleftmargin=2mm,
  columns=fullflexible,
  breaklines=true,
  upquote=true,
  basicstyle=\ttfamily\footnotesize,
  literate={"}{{\textquotedbl}}1

ssh-keygen -t ed25519 -C "你的邮箱"
\end{lstlisting}
提示时一路回车，使用默认文件名。公钥是一整行，从 \verb|ssh-ed25519| 开头，到邮箱结尾：
\begin{lstlisting}[

cat ~/.ssh/id_ed25519.pub
\end{lstlisting}

\begin{lstlisting}[

  xleftmargin=2mm,
  framexleftmargin=2mm,

\paragraph{没有推送权}
对方先 Fork，得到自己名下的一份，clone 到本地，改完 push 到他自己的远程仓库，再在网页上向主仓库提交 Pull Request。你看过差异后，在网页上合并。

\subsection{同时推到 GitHub 和 Gitee}
一个 \verb|origin| 可以有多条 push 地址，fetch 仍指向其中一处。第一行填当前仓库的 SSH 地址，第二行填另一个网站的地址。只加第二行的话，原来的推送地址会被换掉。

\section{基本思想和历史}
\begin{itemize}
\item \TeX：一种宏语言。作者 Donald E. Knuth（高德纳），为写作 TAOCP（《计算机程序设计艺术》）而发明。
\item \LaTeX：\TeX 中的一个宏集合，是\TeX 中的一种格式，建立在\TeX 基础上；每一个\LaTeX 命令最后都会被解释成若干甚至上百个\TeX 命令。
\item pdf\LaTeX、Xe\LaTeX 等是排版引擎，用来编译用\LaTeX 格式写的 \texttt{.tex} 文件。
\end{itemize}

应用思路：
\begin{itemize}
\item 从格式上完全解放出来；
\item 特别适合进行大量的公式编辑；
\item 积累自己的成长型一手资料。
\end{itemize}

我觉得它与Word的最大不同，应该是输入的方式了。它是靠直接“说”来代替Word中的那些不断缓慢的操作。比如：Word中改变字的颜色，是靠操作来完成的，选则相应的文字，然后去点击一些操作图标。而它是在要改变颜色的那段直接写上“换成某某颜色”的命令。这样书写公式就很简单，它可以像我们读公式一样，直接输上去就行了。比如$\sqrt{2}$，它可以直接输类似“根号2”的命令，即：\verb|$\sqrt{2}$|。也就是说一切操作只靠键盘就可以完成，甚至鼠标都不用点。这样是极大提高工作效率。对于那些老手来说，一路敲过去，转换出来就是漂亮的排版了。这样输公式爽多了。但要记住一堆命令。初学起来就不习惯了。

但是我觉得这还是个历史产物。以后随着技术不断先进，手写功能越来越强大，将是与手写识别相结合的情况。直接手写输入公式，就可以转换成自己想要的效果。对于一些微调又可以用命令来做。

\chapter{Vim——终端里的文本编辑器}
\section{基本认识}
在没有图形界面的服务器上改配置、写提交说明、看日志，通常只能用终端里的编辑器。Vim 就是干这个的。Git 写提交说明、\verb|crontab -e|、远程改 \verb|.bashrc|，默认弹出来的往往就是它。

它和记事本、VS Code 的差别，主要不是命令多，而是按键有两种身份：
\begin{itemize}
\item 普通模式：按键是命令。移动、删除、保存都在这里。文件一打开就停在这个模式，这时候打字不会写进正文。
\item 插入模式：按键才是文字。左下角出现 \verb|-- INSERT --|，表示正在打字。
\end{itemize}
从插入模式回到普通模式，按 \verb|Esc|。不确定现在在哪个模式，就多按几次 \verb|Esc|，先回到普通模式再操作。

零基础不要先背命令表。先走通一条路：打开、打字、保存、退出。其余用到再查。Vim 自带一份大约半小时的练习，在终端执行 \verb|vimtutor|。想看中文可以试 \verb|vimtutor zh|，没有中文稿就做英文版。

\section{打开、打字、保存、退出}
Ubuntu / Debian 上安装：\verb|sudo apt install vim|。macOS 和多数 Linux 服务器里已经有 \verb|vim| 或 \verb|vi|。

\begin{verbatim}
vim 文件名
\end{verbatim}
文件不存在时会新建。打开后先处于普通模式。

\begin{itemize}
\item \verb|i|：在光标前进入插入模式，然后正常打字。
\item \verb|Esc|：回到普通模式。
\item \verb|:w| 然后回车：保存。
\item \verb|:q| 然后回车：退出。还有未保存的修改时，它会拒绝退出。
\item \verb|:wq| 然后回车：保存并退出。
\item \verb|:q!| 然后回车：不保存，强制退出。改乱了就用这个离开。
\end{itemize}
冒号开头的命令要在普通模式下输入，左下角能看到正在打的 \verb|:w|。

Git 弹出 Vim 让你写提交说明时，同样是：按 \verb|i| 写完，\verb|Esc|，再 \verb|:wq|。

\section{移动和修改}
这些都在普通模式下使用。方向键可以移动光标；熟悉以后再用 \verb|h|、\verb|j|、\verb|k|、\verb|l|，分别是左、下、上、右。日常小改动记住下面这些就够：

\begin{itemize}
\item \verb|w| / \verb|b|：跳到下一个词 / 上一个词。
\item \verb|0| / \verb|$|：本行行首 / 行尾。\verb|gg| / \verb|G|：文件开头 / 文件末尾。
\item \verb|x|：删除光标上的一个字符。\verb|dd|：删除整行。
\item \verb|u|：撤销。\verb|Ctrl-r|：把刚才的撤销做回去。
\item \verb|yy|：复制当前行。\verb|p|：贴到当前行的下一行。
\item \verb|/关键词| 然后回车：从光标往下查找。\verb|n| 是下一处，\verb|N| 是上一处。
\end{itemize}
命令区分大小写。\verb|dd| 是删掉一整行。

还有两个进入插入模式的方式，都要先按 \verb|Esc| 确认自己在普通模式：
\begin{itemize}
\item \verb|a|：从光标后开始写。
\item \verb|o|：在下面新开一行再写。
\end{itemize}

\section{从网页粘贴进来}
在插入模式里直接粘贴，自动缩进有时会把每一行再缩进一次，代码会越贴越乱。先按 \verb|Esc|，输入
\begin{verbatim}
:set paste
\end{verbatim}
再按 \verb|i|，用终端自己的粘贴（常见是 \verb|Ctrl+Shift+V|）。贴完按 \verb|Esc|，然后输入
\begin{verbatim}
:set nopaste
\end{verbatim}
把自动缩进恢复。\verb|paste| 不要一直开着，否则之后换行时的自动缩进也会停掉。
